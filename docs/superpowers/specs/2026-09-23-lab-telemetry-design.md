# 科研设备遥测与实时监控设计

## 目标

基于本地 Drogon 1.9.13 源码，交付一个可本机演示的个人项目：模拟科研设备以目标 1 ms 间隔采样，经长连接上报；多个浏览器监控端按设备订阅最新指标。保留真实测试证据，形成可追问的简历材料。

## 事实边界

- 设备是模拟器，未接入真实科研仪器。
- 1 ms 是模拟器的目标采样间隔；实际发送速率、服务端接收速率和端到端延迟必须分别测量。
- 监控端以 50 ms 为周期接收该周期的最新值，不承诺逐点可视化。
- 单进程、内存存储、本机监听；不宣称持久化、跨节点、生产认证或硬实时保证。

## 架构

```text
Python 设备模拟器 -- WebSocket /ws/ingest?device_id=... --> Drogon 服务
                                                    ├─校验 id/seq/时间戳/数值
                                                    ├─每设备 256 条内存环形记录
                                                    ├─HTTP 最新值与统计接口
                                                    └─50 ms 最新值分发器 --> /ws/monitor?device_id=... --> 多浏览器监控页
```

上报接口接受 JSON：`{"seq":1,"timestamp_ms":1760000000000,"metrics":{"temperature_c":22.4}}`。设备 ID 1–64 位，仅英文字母、数字、`-`、`_`；序号为非负整数，必须逐设备递增；时间戳为非负毫秒整数；1–32 个有限数值指标。单条消息最多 16 KiB，最多 1024 台设备。

拒绝的数据不覆盖最新值；服务端累积接收、拒绝与订阅数。监控端连接后收到当前最新快照，此后每 50 ms 最多收到一条该设备最新采样；消息包含序号、设备时间和服务端接收时间，前端据此显示实时性与序号跳跃。

## 演示与验证

1. 一条命令构建，一条命令启动服务，浏览器打开 `/`。
2. 启动两台模拟设备；在两个浏览器窗口订阅同一台设备，第三个窗口订阅另一台设备。
3. 展示最新值、曲线、连接状态、接收与拒绝计数；发送重复序号验证拒绝。
4. 自动化集成测试覆盖有效数据、重复序号、非法字段、按设备隔离、多监控连接与断线清理。
5. 性能记录保存测试机配置、目标与实际采样速率、服务端接受速率、端到端 p50/p95/p99、连接数和错误数。指标不达标时保留原始结果。

## 实现边界

应用位于独立仓库，通过 CMake 引用本地 Drogon 源码，不修改 Drogon 框架文件。Trantor 是原 Drogon 仓库声明的依赖，需补齐。监控页使用原生 HTML/CSS/JS，不增加前端打包依赖；设备模拟器使用 Python `websocket-client`。
